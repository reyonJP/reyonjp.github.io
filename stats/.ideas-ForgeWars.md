## 第1回（2026-10-08）

### 1. K/D をキット・プレイヤー単位でも集計する ─ 優先度：高 / 工数：中
- **何を**：キル・デスは今は試合タブで表示するだけ。キット表とキット詳細に「平均キル」「平均デス」「K/D」、プレイヤータブに「通算 K/D」とキット別 K/D を足す。
- **なぜ**：09/26 以降の試合は記録があり、勝率・ダメージに次ぐ強さの指標になる。データが増えるほど価値が上がる。
- **どう**：`perMin` と同じく「記録のある出場だけで分母を取る」集計（`kd.create/addPick/value`）を作り、`derive.kitStats` / `playerProfile` に足す。記録のない出場は分母に入れない。記録がないキット・期間は「記録なし」表示（試合タブと同じ扱い）。各値には「◯試合分」と母数を添えて、少ないデータだと分かるようにする。

### 2. 表示状態を URL に残す（共有リンク） ─ 優先度：中 / 工数：中 ✅ 実装済み（2026-10-08、未コミット）
- **何を**：タブ・選択キット・試合・プレイヤー・統計期間を URL の `#` 以降に保存し、そのリンクを開けば同じ画面になる。
- **なぜ**：「この試合見て」「この期間のネクター」を Discord 等で共有できる。リロードしても選択が消えない。
- **どう**：`#tab=match&match=bb293b69&from=2026/09/19&to=2026/10/03` のような形。`select*` / `changePeriod` / `switchTab` で `history.replaceState`、`init` の最後で読み取って反映。存在しない ID は無視して先頭にフォールバック。

### 3. スマホ幅での表示を実機で確認する ─ 優先度：中 / 工数：小〜中
- **何を**：以前の報告で「スマホ幅でページ全体が横にはみ出す」と書いたが、ヘッドレス Edge が実際は幅 492px で描画していたため、スクショの見え方による誤判定だった可能性が高い（492px では横はみ出しなし）。
- **どう**：実機（または開発者ツールのデバイスモード 375px）で、ヘッダーのボタン・タブ・キット表の4列・期間スライダーを確認。はみ出すならヘッダーのナビ折り返し、キット表の横スクロール化を検討。

## 第2回（2026-10-08）観点：データ表示の誤解しやすさ（サンプル数）

**確認したこと**：統計期間を 10/03 の1日だけにすると、キット表は「グリード 勝率 100.0%」「ガイザー 0.0%」と表示されるが、どちらも **2ピック** しかない（ガーディアン・ヘイルは1ピック）。キット表・散布図にはピック数が出ていないので、何試合分の数字なのか読み取れない。苦手・得意キットの表と習熟カーブは試合数を出しているので、そちらは問題ない。

### 4. キット表・散布図にサンプル数を出し、少ない値は薄く表示する ─ 優先度：高 / 工数：小
- **何を**：キット表の勝率セルに「63.6%（33）」のようにピック数を小さく添える。ピック数が少ない（例：10未満）行の勝率と毎分ダメージは文字とバーを薄くし、ツールチップで「サンプルが少ないため参考値」と出す。散布図の点も同じ基準で半透明にし、ツールチップにピック数を出す。
- **なぜ**：統計期間スライダーで短い期間を選べるようになったため、1〜2ピックの 100%／0% がほかの値と同じ見た目で並び、最強・最弱キットだと誤解されやすい。
- **どう**：`renderKitTable` で `ks.picks(k)` を使い、`td` に `low-sample` クラスと `title` を付ける（CSS：`opacity:.45`）。基準値は `LOW_SAMPLE = 10` の定数にして、`MATCHUP_MIN_GAMES` と同じ場所に置く。散布図は `scatterChart` の点の色に `+'55'` を付ける。

### 5. 勝率で並べ替えるとき、サンプル数の少ないキットを下に回す ─ 優先度：中 / 工数：小
- **何を**：キット表を「勝率」で並べ替えたとき、ピック数が基準未満のキットは基準以上のキットの後ろに置く（`-` のキットはさらに後ろ）。
- **なぜ**：今は 2ピック 100% のキットが一番上に来るので、並べ替えの結果がそのまま誤解につながる。
- **どう**：`renderKitTable` のソート比較を「基準以上か → 値の降順」の2段階にする。毎分ダメージで並べ替えるときも同じにする。案 4 と一緒に実装するのがよい。

## 第3回（2026-10-08）観点：キーボード操作・読み上げ（アクセシビリティ）

**確認したこと**：
- キット表の行は `<tr onclick>` で、`tabindex` がない。そのため Tab キーで行に移れず、キーボードだけではキットを選べない。
- 並べ替えできる列見出し（`sortableTh`）も `<th onclick>` だけで、フォーカスできない。今どの列で並んでいるかは色でしか示されず、`aria-sort` もない。
- 切り替えボタン（ピック率×勝率など）とタブは見た目だけで選択状態を示している。`aria-pressed` や `role="tab"` / `aria-selected` がないので、読み上げでは今どれが選ばれているか分からない。
- グラフ（canvas 6個）には代わりのテキストがない。
- 試合・プレイヤーのカード列と統計期間スライダーは `button` / `input` なので、キーボードで操作できる。

### 6. キット表と並べ替え見出しをキーボードで操作できるようにする ─ 優先度：中 / 工数：小
- **何を**：キット名のセルの中身を `<button type="button">` にし、Tab で移って Enter で選べるようにする。列見出しの中身も `<button>` にし、並んでいる列には `aria-sort="descending"`（キット名なら `ascending`）を付ける。
- **なぜ**：キット表はキットタブの入口なのに、マウスがないと使えない。ボタンにすれば、フォーカスの枠や読み上げはブラウザが標準で対応してくれる。
- **どう**：`renderKitTable` のキット名セルを `<td><button class="row-btn" onclick="selectKit(…)">` にし、行全体のクリックはそのまま残す。CSS で `.row-btn` を見出しと同じ見た目（`appearance:none` など）にする。`sortableTh` は `<th aria-sort=…><button>…</button></th>` を返すように変える。使用プレイヤー表・プレイヤーのキット別表も同じ関数を使っているので、まとめて直る。

### 7. 切り替えボタンとタブの選択状態を読み上げに伝える ─ 優先度：低 / 工数：小
- **何を**：`syncToggle` で `aria-pressed` を、`switchTab` で `role="tab"` / `aria-selected` を、選択状態に合わせて付ける。
- **どう**：数行の追加で済む。カード列の `syncStrip` はすでに `aria-selected` を付けているので、同じやり方にそろえる。

### 8. 試合リンクで試合が見つからないときにメッセージを出す ─ 優先度：高 / 工数：小
（観点外。チャットでの相談で出た案を記録しておく）
- **何を**：`#match=<ID>` で開いたのにその試合がデータにないとき、今は黙って最新の試合を表示している。これを「この試合はまだ反映されていません。数秒後に再読み込みしてください」という表示と再読み込みボタンに変える。
- **なぜ**：ゲーム終了時に「今回の統計はこちら」のリンクを送る連携を予定している。記録がスプレッドシートを経て反映されるまでに時間がかかるので、直後にクリックすると1つ前の試合が「今回の試合」として表示され、誤解される。
- **どう**：`readHash` で、指定された match が見つからなかったことを `state.match.missing` に保存する。`renderMatch` は、それがあれば試合表示の代わりに案内を出す。別の試合カードを選んだら解除する。
